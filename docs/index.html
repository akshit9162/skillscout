Agent skills · weekly · safe by default

AI tooling moves weekly. Keep your agent current.

New skills, plugins and agent workflows land on GitHub every day, and the ones you installed keep changing upstream. skillscout checks the ecosystem every week against what you work on, tells you what's new and worth having, and diffs what changed in the skills you already use. Because a skill runs with your permissions, it also scans every file, installs nothing without your approval, and pins each install to an exact commit.

The problem

Last month's best practice is already stale

The agent tooling ecosystem moves faster than anyone can follow: new skill repos every day, plugin marketplaces, curated lists with hundreds of entries, and the skills you already installed changing under you. Checking it by hand means watching hundreds of repos. Not checking means your agent works the way it did months ago.

Moving fast has a catch. Each skill is text your agent obeys with your permissions, and many ship scripts and hooks. So skillscout keeps you current the way a package manager keeps dependencies current: find, check, pin, and diff every update.

Keeping up

What a week looks like

01Monday 10:00launchd runs discover; you get a notification
02New since last runOnly the skills that appeared this week and fit your work
03ShowFlags with file and line, the full SKILL.md, overlaps
04ApproveCopied and pinned to its commit
05Upstream changesupdates shows the diff; nothing applied
06Take itRe-scanned, then replaced

The loop

Discover, scan, score, approve, pin

01DiscoverGitHub topic searches plus your trusted repos
02CloneSparse and shallow: skill folders only; nothing runs
03ScanEvery file, every line, three risk levels
04ScoreRelevance to your keywords, stars, freshness
05ApproveYou pick; symlinks dropped
06PinCommit + content hash in a lockfile

Your profile decides

A TOML file of keywords and weights from your own work. Relevance is 65% of the score; stars and freshness are 35%.

Conflicts caught

Same-name skills and descriptions similar enough to fire on the same prompt are flagged against what you already have.

Cheap to run

Sparse clones fetch only skill folders, minus media and archives, eight repos at a time.

Guarantees

What it will never do

Install without approve

Discovery only writes a report. Every install is one explicit command for one skill.

Overwrite your own skills

approve refuses a folder it didn't install, checked against the lockfile's content hash.

Follow symlinks

A symlink in a skill could point at ~/.ssh. They're flagged in the scan and dropped on copy.

Apply updates silently

updates prints a diff. Taking one re-runs the scan: an update that adds sudo rm -rf / is refused, and the tests check it.

Get it

Install

As a Claude Code plugin, so your agent runs the loop and asks before every install:

claude plugin marketplace add akshit9162/skillscout
claude plugin install skillscout@skillscout

As a CLI:

pipx install git+https://github.com/akshit9162/skillscout
skillscout init          # then edit [keywords] in ~/.skillscout/profile.toml
skillscout discover
skillscout show <id>
skillscout approve <id>
Honest scope

Limits

Pattern matching

The scanner catches known patterns. It can't prove a skill is safe, so read show before approving.

Keyword relevance

Ranking uses your keywords, not semantic search. Tune the weights in your profile.

Context cost

Every installed skill's description loads into every session. Keep the total to a few dozen.
